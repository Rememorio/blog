Codex 源码阅读系列

这个系列从 openai/codex 的公开源码进入，不先贴功能清单，而是跟一条普通请求走： 它怎样从一句话变成有类型的任务，怎样进入会话和工作单元，怎样整理上下文、暴露工具、 经过权限关口，并把过程留下给客户端展示和后续恢复。

第一篇 先跟一次请求走完 Codex 的运行主线

先把一个普通修 bug 请求拆成几道关口：入口、protocol、session、turn、 上下文、工具权限、事件和持久记录。

第二篇 上下文不是聊天记录，而是运行时账本

从 ContextManager、TurnContext、for_prompt() 和 compaction replacement 读懂 Codex 的上下文管理。

第三篇 protocol 与事件流，客户端怎样共享同一套事实

从 TurnStartParams、Submission、Op、 EventMsg 到 app-server v2 projection 和 rollout 恢复。

第四篇 工具调用背后的运行时合约

从 ToolSpec、ToolRouter、ToolRegistry、 ToolInvocation 到 approval、sandbox、events 和 history。

第五篇 权限与 sandbox，副作用怎样被运行时收口

从 approval_policy、permission hooks、ToolOrchestrator、 SandboxAttempt 和 retry 读懂副作用工具的运行时边界。

第六篇 客户端投影，同一套事实怎样变成可见状态

从 EventMsg、TurnItem、ThreadItem、 ServerNotification、TUI history cell 和 rollout 恢复读懂客户端看到的状态。

第七篇 扩展与多 agent，额外能力怎样进入一次 turn

从 skills、plugins、MCP tool exposure、 tool_search、dynamic tools 和 AgentControl 读懂扩展能力怎样接进同一条运行主线。

第八篇 Hooks 与生命周期，边界处还能改变什么

从 HookEventName、hook discovery、HookStarted、 HookCompleted、prompt gate、tool gates、compact 和 Stop 读懂 hooks 怎样接回 turn 主线。

第九篇 性能与 prompt cache，速度来自请求形状

从 OpenAI prompt caching 契约、prompt_cache_key、 stable prefix、dynamic tail、compaction 和 token usage 指标读懂 Codex 怎样把体感速度压回请求形状。

第十篇 rollout 与恢复，能继续的前提是能重放

从 RolloutItem、JSONL writer、InitialHistory、 reverse scan、replay suffix、rollback marker 和 fork snapshot 读懂 Codex 怎样把一次 thread 留成可恢复证据。

第十一篇 SDK 与 app-server，外部调用怎样进入同一套 runtime

从 app-server 的 initialize、typed ClientRequest、 thread/start、turn/start、listener 和 Python / TypeScript SDK，读懂外部应用怎样接入同一套 runtime。

阅读路线

第一阶段完整路线

  1. 先用总览建立一次 turn 的主线，再读上下文、protocol、工具和权限。
  2. 随后进入客户端投影、扩展、hooks、性能与 prompt cache、rollout 恢复。
  3. 最后用 SDK 与 app-server 收尾：外部调用方怎样进入同一套 runtime。
