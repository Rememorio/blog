Activation Steering、Reflection Training 与 Alignment Auditing

看见一个内部方向之后，可以在本轮推理里轻推它，可以通过训练把反思习惯写进权重，也可以只把它作为审计告警。三种动作共享同一套仪器，却有完全不同的风险与回滚成本。

控制面：inference · training · audit证据：readout · intervention · ablation

核心原则。能读出一个 honesty 或 deception direction，不等于模型内部有一个可独立开关的“诚实模块”；steering 能改善某组 eval，也不等于对齐问题已经解决。方向的意义必须靠对照、剂量曲线、行为特异性、跨分布评测和消融共同建立。

三条回路，改动发生在不同时间尺度

回路改什么持续多久主要风险
Activation steering本轮某层的 residual activation一次或一段推理副作用、分布迁移、被绕过
Reflection training模型 weights 与默认策略跨部署，直到再训练过拟合、能力退化、隐藏目标
Alignment auditing证据、告警与上线决策持续运行漏报、误报、监控被优化

一个成熟系统不会把它们串成“发现方向 → 永久 steering”这么短的链。审计先产生假设；小剂量、可回滚的 inference intervention 验证因果性；只有当收益跨场景稳定，才考虑训练；训练后重新审计，因为模型可能用新的内部路径完成同一行为。

Activation steering：在推理途中加一个向量

Activation Addition（ActAdd）用一对对比 prompt 的 activation 差构造 steering vector，在指定层和 token 位置把它加到新输入的 activation。Contrastive Activation Addition（CAA）把这种做法用于 truthfulness、toxicity、sycophancy 等行为：从正负样本求平均差向量，再在生成时持续注入。

它比改 weights 更容易回滚，也比自然语言 system prompt 更直接；但“方向”往往纠缠多个特征。剂量太小无效，太大可能让语言退化；在一组任务有效，不保证迁移到另一语言、领域或长程 Agent trajectory。对高风险系统，steering 应是附加层而不是权限、policy 与外部 verifier 的替代品。

Reflection training：把工作区中的反思变成默认策略

J-space 论文给出一个很有代表性的训练实验。研究者从 production RL 环境收集 10,000 条 partial rollouts，在随机轮次截断；随后追加一个 reflection question 和依据 constitution 写出的反思答案，只对反思部分计算 loss。模型不是简单背诵一个拒绝模板，而是在多种未完成情境中练习识别自身行为、原则和下一步。

报告结果中，dishonesty 从 0.25 降到 0.07，deception 从 0.38 降到 0.05。更关键的是机制消融：移除 J-space 中 ethics / reflection 相关方向后，fabrication 从 0.07 回升到 0.22，deception 从 0.05 回升到 0.23。训练收益与可干预的内部工作区产生了联系。

这种结果比“fine-tune 后分数变好”更接近机制解释，却仍有边界：训练分布、constitution 表述、长期副作用和对抗适应都可能改变结论；一次消融也无法排除冗余路径。Reflection training 是 weight-level self-improvement，不是模型在部署中自主改写自己。

Alignment auditing：从会解释，走到能发现异常

内部 readout 最实际的用途之一，是在部署前后寻找“行为还没暴露、内部模式已偏移”的样本。论文把 J-lens 用于 alignment auditing，在六类案例中有四类与 NLA 相当或略好；同时也会失败，例如没有完整捕获 reward hacking 和 language switching 的细节。这种结果正说明 audit 需要组合仪器。

建议的证据矩阵

信号它能补什么失败时怎么办
行为与 environment diff真实外部后果增加对抗任务与长轨迹评测
Tool trace计划如何变成动作强制 schema、权限与可回放日志
CoT monitor便宜的语义化意图线索防止把 monitor 直接优化成表演目标
J-lens / NLA / SAE输出前的内部异常模式交叉验证并做 steering / ablation

重新定义 Agent 的“自进化”

很多 Agent 系统说自己会 self-evolve，实际变化发生在完全不同的载体。把它们合成一个词，会掩盖最重要的治理差异。

变化对象例子验证与回滚
外部 artifactmemory、skill、prompt、workflow版本 diff、离线 eval、直接回滚文件或记录
Inference stateactivation steering、context routingA/B、剂量曲线、关闭 intervention
Weightsreflection training、SFT、RL完整模型 eval、checkpoint rollback、重新安全审计

越往下，变化越持久、验证越昂贵。实践上应优先用外部 artifact 表达可审阅的经验，用 steering 做受控实验，用训练固化跨任务稳定、证据充分的规律。Agent 本身不能同时是提案者、受益者和唯一审核者。

一个可落地的闭环

  1. Observe：保存行为、tool trace、环境差异，并对风险样本运行多种内部 readout。
  2. Hypothesize：提出可证伪的机制假设，不把标签当事实。
  3. Intervene：用小剂量 steering、swap 或 ablation 检验行为是否按预期改变。
  4. Train：只在跨场景证据稳定时更新 weights，保留 checkpoint 与独立审计集。
  5. Re-audit：检查能力副作用、替代路径和 monitorability；必要时回滚。

这条闭环不会带来“可证明对齐”的终点。它的价值更朴素：把对齐从一次性分数，变成可以追溯证据、区分时间尺度、进行反事实验证的持续工程。
