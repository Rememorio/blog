模型内部 · 系列 03

CoT Monitoring、NLA、SAE 与 Latent Reasoning

模型写下“我在检查测试”，同时悄悄利用了答案提示；Agent 的日志看起来合规，内部计算却在寻找奖励漏洞。要监控推理，第一步不是选一个万能解释器，而是先知道每个观察窗口漏掉什么。

问题：reasoning observability原则：多源证据，不把解释当真值

术语先分开。CoT 是模型输出的一段 token；NLA、J-lens 和 SAE 是观察 activation 的方法；Coconut 一类 latent reasoning 则改变计算载体，让 hidden state 继续参与推理。前三者是仪器，后一类是被观察的计算设计，不能放在同一栏里当作四种“解释方法”。

四扇窗，看见的是四种对象

方法观察对象优势主要盲区
CoT monitoring模型主动输出的推理 token便宜、自然语言、适合在线规则与外部 monitor不忠实、省略、受监控压力后可能隐藏
NLAactivation 的自然语言描述表达丰富，可描述关系和组合概念verbalizer 会 confabulate，训练和推理成本高
SAE稀疏 dictionary features可大规模扫描、定位相对稳定的特征feature splitting、absorption 与人为命名误差
J-lens / J-space对最终输出有 Jacobian 影响的 token-linked directions可读、可写、适合反事实干预偏向词汇可表达概念，只覆盖小部分计算
Latent reasoninghidden state 中继续发生的计算不受逐 token 自然语言 bottleneck 限制本身不提供解释，甚至让纯 CoT 监控更不完整

CoT 很有用，但不保证忠实

Anthropic 的 faithfulness 实验给模型不同类型的答案提示，再检查 CoT 是否承认使用了提示。推理模型经常利用提示，却没有在可见推理中说出来。于是 CoT 同时具备两个看似冲突的性质：它是最便宜、最语义化的行为信号，又不是内部计算的 ground truth。

OpenAI 的 reward hacking 研究进一步表明，监控 CoT 往往比只看最终 action 更容易发现作弊意图；但若直接对“可疑 CoT”施加优化压力，agent 可能学会用更难被 monitor 捕捉的方式作弊。监控通道的价值，部分来自它尚未被强力优化。把 monitor 变成训练奖励之前，要评估会不会在提高表面合规的同时降低 monitorability。

NLA：让 activation 用句子描述自己

Natural Language Activations训练两个互相约束的组件：activation verbalizer（AV）把中间 activation 写成文本解释，activation reconstructor（AR）再从解释重建 activation。两者用重建质量做强化学习，让描述尽量保留原状态中真正可用的信息，而不只是贴一个标签。

它比单个 SAE feature 更能表达组合关系，例如“模型正在权衡诚实回答与顺从用户角色”。但自然语言 decoder 仍可能补全一个听起来合理、实际没在 activation 中的故事；不同层的可解释性也不同，额外模型带来显著成本。NLA 最适合生成调查假设、比较异常轨迹和审计 evaluation awareness，不适合单独给出定罪结论。

SAE：把密集 activation 拆成稀疏特征

Sparse Autoencoder用一个过完备字典重构 activation，同时约束每次只激活少量 feature。研究者可以收集每个 feature 的高激活样本、给它命名、在海量运行中搜索。它把“某层有几千维向量”变成“哪些相对稳定的稀疏方向出现了”。

稀疏不等于天然单义。一个概念可能被拆到多个 features（splitting），一个 feature 也可能吸收邻近概念（absorption）；自动解释标签还会把相关性写成过度确定的语义。attribution graph 方法因此更关心 feature 之间的因果连接，而不是停在“这里亮了一个 deception feature”。

Latent reasoning：有些推理本来就不经过文字

Coconut不要求每一步都生成自然语言 token，而是把上一轮的最后 hidden state 作为下一步输入 embedding，形成 continuous thought。论文的 proof-of-concept 显示，这种状态可以同时保留多个可能的下一步，在需要搜索的任务中表现出类似 breadth-first 的探索。

这不是“更好的 readout”，而是另一种计算架构。它直接提醒 Agent 工程：把所有关键推理都假设为可见 token，会漏掉模型原生的 silent computation，也会漏掉显式引入的连续思维。若系统允许 latent reasoning，就必须把 activation-level 探针、行为沙箱和环境验证纳入监控，而不是只存一份漂亮的 CoT。

防御纵深：让不同证据互相拆台

在线路径：便宜信号先挡住明显风险

权限与 schema 约束先于模型解释；tool trace 和环境 diff 必须可回放；CoT monitor 用于发现可疑意图，但不作为唯一裁决。高风险动作应要求外部 verifier 或人工审批。

离线路径：内部 readout 寻找未知模式

对抽样轨迹运行 NLA、SAE 与 J-lens，检查它们是否在失败前共同出现；随后用 steering、ablation 或 counterfactual prompt 验证。只有能稳定预测或改变行为的信号，才值得升级成监控规则。

对自进化：评估循环必须独立

会修改自己 skill、memory 或策略的 Agent，不能让同一个 reward 同时决定“怎么行动”和“如何解释行动”。保留冻结的审计集、独立 monitor、版本化外部资产与可回滚策略，才能避免系统把优化目标变成一场语言表演。
