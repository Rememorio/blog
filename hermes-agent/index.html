Hermes Agent: 自进化 Agent 是怎样长出来的

Hermes 最值得拆的不是“工具多”，而是它把一次任务里的经验分成 memory、skills、session search 三类长期载体，再用后台 review 和 curator 把经验带进未来任务。

01

先抓主线：自进化不是一句口号

一个 Agent 会用工具，只能说明它能完成当前任务。Hermes 更有意思的地方在下一步： 这次任务里出现的用户偏好、环境约定、排错路径、可复用流程，能不能在下一次任务开始前就已经存在。

这条主线可以压成五步：任务产生 transcript；稳定事实进入 memory；可复用方法进入 skills； 旧现场通过 session_search 回忆；后台 curator 整理 agent 自己创建出来的技能库。

03

先把三个边界讲清楚

读 Hermes 的自进化模块，最重要的是不要把长期资产混成一个桶。 同样来自一次任务的信息，会因为未来价值不同，进入不同系统。

04

运行时骨架

自进化不是每轮都让模型随便写长期资产。Hermes 在 turn_context.py 里推进 memory 计数，在 conversation_loop.py 里推进 skill 计数，在 turn_finalizer.py 里等最终回答完成后再触发后台 review。

后台 review 的实现位于 background_review.py。 它继承父 agent 的运行时和 cached system prompt，但禁用递归 nudge、禁用 compression，并把工具限制到 memory 与 skills。 这就是 Hermes 能学习、但不让学习流程抢走当前任务控制权的关键。
